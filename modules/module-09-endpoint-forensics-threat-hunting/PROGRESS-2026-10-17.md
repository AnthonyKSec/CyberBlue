## Principle before platform

**Detection coverage requires a working event-generation and collection chain.** Static artifact inventories describe what exists or is configured; historical event logs support what occurred and when. A zero-result query is an *observation*, not proof of no activity. Correctly diagnosing missing telemetry requires checking the source's collection policy and event-generation conditions, creating an authorized benign stimulus, checking local records, and checking the downstream collector.

```text
Define investigation scope → Collect inventory → Review event evidence
  → Identify telemetry gap → Inspect logging policy → Enable narrow logging
  → Generate controlled test → Correlate local events → Collect centrally
  → Verify test cleanup → Preserve and document findings
```

## C. Scheduled-task event visibility failure and recovery — Steps 09.63F–N

### Baseline and detection gap

Previously inventoried **257 configured tasks** with `Windows.System.TaskScheduler`; existence is not proof of execution.

Initial `Windows.EventLogs.ScheduledTasks` collection: completed, **0 results**, ~4.18 sec, 31,925 rows scanned, no errors visible. The absence of results prompted source-side checks rather than a false conclusion that tasks never executed.

Read-only Windows PowerShell:

```powershell
Get-WinEvent -ListLog 'Microsoft-Windows-TaskScheduler/Operational' |
  Select-Object LogName, IsEnabled, RecordCount, LogMode, MaximumSizeInBytes

auditpol /get /subcategory:"Other Object Access Events"
```

Observed Task Scheduler Operational: `IsEnabled=False`, `LogMode=Circular`, `MaximumSizeInBytes=10485760`, no RecordCount reported. Separate Security audit policy `Other Object Access Events = No Auditing`. These are **two configuration limitations**; policy state does not establish that the artifact's first zero-result count was solely caused by either one.

### Narrow remediation and local validation

Authorized lab configuration change (Administrator PowerShell):

```powershell
wevtutil sl "Microsoft-Windows-TaskScheduler/Operational" /e:true
```

Verified `IsEnabled=True`; immediately afterward `RecordCount=0`, consistent with an empty newly enabled log. **Security auditing was left unchanged**.

Controlled test task `CyberBlue-Module09-TelemetryTest` registered and invoked by the operator; one action only, `C:\Windows\System32\cmd.exe /c exit 0`, no download or destructive action. Windows PowerShell `Get-WinEvent` filtered from the test start and identified Task Scheduler Operational events **110**, **201** and **102**, including action exit code **0**.
