## Principle before platform

**An enrolled endpoint is not an investigated endpoint.** A defensible DFIR baseline requires trusted enrollment, remote artifact collection, process/network/service attribution, a recorded evidence trail, explicit scope limitations, and analytical interpretation. Velociraptor implements those capabilities for this CyberForge training environment; it does not substitute for analyst judgment.

```text
AUTHORIZE → BASELINE → COLLECT → VERIFY → INVESTIGATE
    → CORRELATE → DOCUMENT → REPORT → RESET → REPLAY
```

## Investigation 1 — process lineage

The `Windows.System.Pslist` baseline includes: `System` PID 4; `Registry` PID 100; `smss.exe` PID 368; `csrss.exe` PID 556; `wininit.exe` PID 668; plus additional `csrss.exe` instances PID 676 and 3160.

A notebook query scanned 187 rows and showed two children whose `Ppid=524`: `csrss.exe` PID 556 and `wininit.exe` PID 668. The wider query also showed `csrss.exe` PID 676 (`Ppid=660`) and PID 3160 (`Ppid=7920`). A targeted query for `Pid IN (524,660,7920)` returned **zero rows** in this point-in-time snapshot.

**Conclusion:** The snapshot does not identify those historical parents; short-lived Windows session-manager processes are a plausible, not proven, explanation. Historical Sysmon process creation or Security 4688 records would be needed to corroborate parent identity, if retained. No malicious behavior is established by these records.

The network and service collection times differ (~28 minutes). PID matching with names and executable paths is good corroboration but is **not a single unified event timeline**. A socket listed ESTAB is not proof of legitimate remote authorization.

## Investigation 3 — scheduled-task persistence triage

`Windows.System.TaskScheduler` returned **257** rows. A VQL filter looking for command interpreters, PowerShell and LOLBins returned **15 task records** for manual review. Visible entries largely matched standard Windows maintenance behaviors: AppX cleanup, Autochk, SharedPC, Application Experience, SMB1 cleanup, DiskDiagnostic, SysMain, Windows device join/recovery, StateRepository.

**Important detection engineering lesson:** Query matching `cmd.exe` also matched `dsregcmd.exe` tasks, illustrating a regex/substring false-positive that should be corrected in future query tuning.

A separately observed `DispatchBoard Import` scheduled task was explained by the operator as associated with their Claude Desktop workflow; its exact script and executable trust are **not yet independently validated**. The 15 selected tasks are not a complete audit of all 257 tasks. No task was deleted, modified or disabled.
